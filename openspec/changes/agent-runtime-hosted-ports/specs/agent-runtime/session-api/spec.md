## Purpose

为宿主提供稳定的北向会话接口：宿主只依赖本运行时的公开接口即可开会话、执行轮次、控制进行中的轮次并关闭会话，不直接依赖上游 Agent 内核的内部路径与私有属性。

## ADDED Requirements

### Requirement: 宿主只依赖公开接口
运行时 SHALL 通过公开包导出宿主所需的全部入口、值对象、事件类型与异常类型；导入这些公开模块 MUST NOT 触发上游 Agent 内核模块（`run_agent`、`agent.*`、`tools.*`）的导入。

#### Scenario: 导入公开包不加载上游内核
- **WHEN** 宿主在全新进程中导入运行时公开包
- **THEN** 进程内不存在 `run_agent`、`agent`、`tools` 模块

#### Scenario: 宿主代码无需上游导入
- **WHEN** 对示例宿主代码执行边界 import 检查
- **THEN** 检查通过，示例宿主不包含对 `run_agent`、`agent`、`tools` 的导入

### Requirement: 会话规格在开会话时一次性生效
运行时 SHALL 在开会话时按不可变的会话规格创建会话，会话存续期间规格 MUST NOT 变化。规格中的透传参数 MUST 在开会话时按上游构造签名校验，未知参数 MUST 在任何模型调用之前报错。

#### Scenario: 未知透传参数被拒绝
- **WHEN** 宿主在透传参数中提供上游构造签名不存在的键并开会话
- **THEN** 开会话失败并返回指明该键的错误，且未发出任何模型请求

#### Scenario: 上游新增参数经透传生效
- **WHEN** 宿主在透传参数中提供上游构造签名中存在、但规格值对象尚未收录的键
- **THEN** 会话创建成功，且该值传递给上游

### Requirement: 历史由宿主持有
每次执行轮次时，宿主 MUST 提供完整的对话历史（首轮可为空列表）。运行时 MUST NOT 以自身保存的历史替代宿主提供的历史，MUST NOT 修改宿主传入的历史对象，并 SHALL 在结果中返回本轮结束后的完整消息列表。

#### Scenario: 缺少历史参数
- **WHEN** 宿主执行轮次时未提供历史
- **THEN** 调用失败并返回参数错误，且未发出任何模型请求

#### Scenario: 宿主历史不被修改
- **WHEN** 宿主传入历史列表执行一轮对话
- **THEN** 轮次结束后宿主持有的原列表内容与调用前一致

#### Scenario: 以返回消息驱动多轮
- **WHEN** 宿主把第一轮结果中的完整消息列表作为第二轮的历史
- **THEN** 第二轮模型请求中包含第一轮的用户与助手消息，且角色严格交替

### Requirement: 历史改写与会话标识变化必须显式透出
当本轮返回的消息列表不再以宿主传入的历史为前缀时（例如发生上下文压缩），运行时 SHALL 在结果中标记历史已改写。结果 SHALL 包含本轮结束时的会话标识；标识与开轮时不同时 MUST 同时给出变化前后的值。

#### Scenario: 压缩后标记历史改写
- **WHEN** 本轮发生上下文压缩，返回的消息列表与传入历史的前缀不一致
- **THEN** 结果标记历史已改写，宿主据此以返回的消息列表整体替换本地历史

#### Scenario: 会话标识轮换
- **WHEN** 配置了会话存储且本轮压缩导致上游轮换会话标识
- **THEN** 结果同时给出旧会话标识与新会话标识

### Requirement: 模型侧失败通过结果表达
模型侧失败（额度不足、内容策略拦截、上下文溢出、压缩暂缓或耗尽、被中断等）SHALL 通过结果字段表达，并提供是否可重试的判断。只有运行时无法继续的情况 MAY 抛出异常，且异常 MUST 保留上游原始异常作为原因。

#### Scenario: 不可重试的失败
- **WHEN** 上游返回失败且标记为不可重试
- **THEN** 结果标记失败、给出失败原因且可重试为假，调用本身不抛异常

#### Scenario: 压缩暂缓
- **WHEN** 上游因压缩暂缓结束本轮
- **THEN** 结果标记压缩暂缓且不标记失败

### Requirement: 每个会话复用同一上游实例
同一会话的所有轮次 MUST 复用同一个上游 Agent 实例；在未发生历史改写的前提下，连续轮次发送给模型的系统提示 MUST 字节一致。

#### Scenario: 连续轮次系统提示稳定
- **WHEN** 同一会话连续执行两轮且未发生压缩
- **THEN** 两轮模型请求中的系统提示字节完全一致

### Requirement: 同一会话的轮次串行执行
同一会话的轮次 MUST 串行执行。并发请求 SHALL 按会话配置的策略处理：默认排队，拒绝策略下 MUST 立即返回会话忙错误。

#### Scenario: 拒绝策略下的并发轮次
- **WHEN** 会话配置为拒绝策略，且在一轮进行中再次发起轮次
- **THEN** 第二次调用立即返回会话忙错误，第一轮不受影响

### Requirement: 进行中轮次的控制
中断、插话、改道、查询中断状态与活动快照 SHALL 可以在轮次执行期间从其他线程调用。插话 MUST NOT 在历史中产生两条连续的同角色消息。

#### Scenario: 从其他线程中断
- **WHEN** 轮次执行中宿主从另一线程请求中断
- **THEN** 本轮尽快结束，结果标记为被中断

#### Scenario: 插话保持角色交替
- **WHEN** 轮次执行中宿主插话，本轮随后正常完成
- **THEN** 返回的消息列表中不存在两条相邻的同角色消息

### Requirement: 事件投递
运行时 SHALL 把流式文本、思考、工具开始 / 进度 / 完成、状态与通知以带类型的事件投递给宿主提供的事件接收方，并在各类型事件中提供稳定的标准化字段。事件接收方抛出的异常 MUST 被记录且 MUST NOT 中断轮次。

#### Scenario: 接收方异常不影响轮次
- **WHEN** 事件接收方在处理流式事件时抛出异常
- **THEN** 本轮仍正常完成，异常被记录

#### Scenario: 工具事件携带标准字段
- **WHEN** 本轮执行了一次工具调用
- **THEN** 宿主依次收到工具开始与工具完成事件，二者均包含工具名

### Requirement: 会话关闭
关闭 MUST 可重复调用，并 SHALL 释放模型客户端、子进程与记忆提供方资源，同时取消该会话全部挂起的交互请求。关闭后对该会话的其他调用 MUST 返回会话已关闭错误。

#### Scenario: 关闭后调用
- **WHEN** 宿主关闭会话后再次执行轮次
- **THEN** 调用返回会话已关闭错误

#### Scenario: 重复关闭
- **WHEN** 宿主对同一会话连续调用两次关闭
- **THEN** 两次调用均成功返回

### Requirement: 特权维护面受控开放
上下文压缩、立即持久化、刷写存储、系统提示失效、后台复盘等维护操作 SHALL 仅在运行时初始化时显式允许后才可获取；未允许时获取维护面 MUST 返回能力不可用错误。

#### Scenario: 未允许时获取维护面
- **WHEN** 运行时未开启维护能力，宿主请求某会话的维护面
- **THEN** 返回能力不可用错误
